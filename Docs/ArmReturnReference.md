# Per-attack arm-return reference

The separate **Set Attack Arm Return Rotation Blend** node can override rotation independently for both position modes: each input is0=pelvis,1=root, with quaternion interpolation between. Until called, the defaults below remain intact. See [rotation controls and the corrected obstacle frame](ArmReturn260AndRotationBlend.md).

`Set Attack Arm Return Pelvis Local` has one checkbox per attack. Checked follows **pelvis position and current root rotation**; unchecked retains the original upper-torso frame. All are false by default. Set **pike=true** to try the extended-arm case. This is per agent, replaces the full selection, and does not enable return by itself. It applies to the original returning arm and the optional additional arm using the existing enable/selection nodes.

Configure before return begins or in Special Ended. Once a return has produced a pose, its reference is latched until completion/cancellation; changing the node affects the next return. This prevents reinterpreting a stored hand transform in a different frame halfway through motion. Reset restores the saved choices and cancels active motion; a new special also cancels it.

The original frame is anatomical, built from pelvis/neck/shoulders, rather than the raw spine_05 bone transform. The checked mode calibrates the chest-height route offset once in root axes. Previous/current origins follow previous/current pelvis positions plus that root-oriented offset, while orientation follows the corresponding root. Pelvis yaw, pitch and roll do not rotate the route or its offset. Root orientation is converted into each publication's mesh component space, preserving the actual world heading. The idle chain is mapped from neutral anatomical torso axes into this same frame, then attached to the actual shoulder with authored lengths and bend intact. This avoids leaking pelvis rotation back through the destination or confusing pelvis bone axes with anatomical forward/up.

Hand translation, orientation and prior hinge transport use the selected frame. Sword winding candidates, final blade clearance and elbow clearance continue to use the actual torso. This is not a world-space lock: pelvis translation, root turns, body clearance, arm reach and the eventual blend back to NN still contribute.

The previous clearance-dependent straight-path experiment was reverted when this node was introduced. The later [target and routing correction](ArmReturnReachAndDirectPath.md) now uses direct clear routes and smooth front wrapping based on actual torso clearance. Existing both-arm controls, rotation winding, elbow reconstruction, initial-distance speed, hold/blend timing and authored settings are preserved.

Reference state exists only for active selected returns. No new timer, inference or inactive pose work; the one existing 60-game-tick-per-second clock is shared by both arms. New state uses weak sidecars rather than changing retained actor or return-state layouts.

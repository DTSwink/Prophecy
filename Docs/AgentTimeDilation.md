# Per-agent time dilation

Implemented and validated through Live Coding, 2026-09-21. Normal editor DLL must include the changes before an approved fresh launch.

`Set Agent Time Dilatation(Agent, Multiplier=1)` and `Get Agent Time Dilatation` control the native managed agent. The Blueprint labels use the user's preferred spelling; native function identifiers remain `SetAgentTimeDilation` / `GetAgentTimeDilation` for existing-node compatibility. A finite positive multiplier is required: 2 doubles locomotion root and NN cadence; 0.5 halves it. Zero, negative and nonfinite inputs fail without changing state. The external Sim Bridge is unsupported.

The trained 1/30-second integration step, encoded trajectory spacing and recurrent features remain unchanged. Agent-local clocks change the frequency of complete lower/upper evaluations. Shared policy boundaries still own attack, parry, dodge and the Armed gate. Inactive lanes retain both recurrent histories. Publication and continuous-root interpolation use each agent's own phase. Future-window time offsets are world seconds, divided by the multiplier; index zero remains the actual displayed root.

Root inputs, direct velocity setters, both magic velocity sets and limits retain agent-local units. Their motion is accelerated together; velocity readbacks report effective world rates. For example, magic velocity100 cm/s at multiplier2 travels at200 cm/s. Auto-run tests the agent-local trajectory speed, just like ordinary Walk/Run selection: changing playback rate alone must not change the checkpoint. Direct world root offsets are still immediate spatial operations.

Specials mean full/half attack, active parry and active dodge. A successful special start resets the configured multiplier permanently to1; it is not restored afterward. Non-1 requests during an active special fail. A queued defense waiting for Armed remains free locomotion and retains its multiplier until the defense actually activates. Failed start requests do not reset speed. Initial-agent reset returns to1 too.

Changing the multiplier preserves the current interpolation phase. Returning to1 finishes the current interval at the next shared policy boundary, then removes the custom clock. Normal/default agents create no time-dilation clock, timer, inference, component or history copies. Shared batched models currently have fixed100-lane tensors; accelerating one agent can require extra full-batch model calls even though only due lanes consume their results. Each clock retains the existing32-step catch-up cap per game tick, so extreme multipliers or long stalls may drop excess catch-up work.

Existing gameplay blend/hold clocks remain60 unpaused game ticks per authored second, independent of this multiplier. They are consumed at most once even if multiple NN steps occur in a tick. This feature does not change Actor CustomTimeDilation, Blueprint event frequency, world timers or input polling.

Physical following uses the faster published targets with the shared Jolt step. Target displacement over world delta yields the accelerated drive velocity; gravity, collisions, free-ragdoll integration and physical damping remain on the common world clock. A completed physics observation is fed back at most once per agent per game tick; taking extra NN steps must not repeatedly apply the same observed error. No per-body physics clock, global substep change or CCD is introduced.

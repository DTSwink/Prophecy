# Unreal C++ Blueprint Node Recovery Procedure

Date: 2026-07-02
Project: `C:\Users\singerie\Documents\Unreal Projects\Prophecy`
Engine: `C:\Program Files\Epic Games\UE_5.7`

## Symptom

After opening Unreal Editor, Blueprint nodes backed by newly added C++ `UFUNCTION` or `UPROPERTY` APIs are red or unresolved. Running a Live Coding build and refreshing nodes makes them work again for the current editor session, but the problem returns after reopening the editor.

## Likely Cause

The base project DLL loaded at editor startup is stale, while the newest reflected C++ APIs only exist in Live Coding patch binaries.

Observed local pattern:

```text
Binaries/Win64/UnrealEditor-GameAnimationSample3.dll        older timestamp
Binaries/Win64/UnrealEditor-GameAnimationSample3.patch_*.exe newer timestamp
```

Live Coding patches code into the running editor. It is useful for `.cpp` body changes, but it is unreliable as the only build path for reflected header changes such as:

```cpp
UCLASS()
USTRUCT()
UFUNCTION()
UPROPERTY()
```

Blueprint nodes depend on Unreal reflection data generated by UHT and compiled into the loaded module. If the startup DLL does not contain the latest reflection data, Blueprints can open with missing or red C++ nodes.

## Recovery Steps

1. Save all open Blueprint/assets in Unreal.
2. Close Unreal Editor completely.
3. Close the Live Coding console if it remains open.
4. Run a normal closed-editor build from PowerShell:

```powershell
& "C:\Program Files\Epic Games\UE_5.7\Engine\Build\BatchFiles\Build.bat" GameAnimationSample3Editor Win64 Development -Project="C:\Users\singerie\Documents\Unreal Projects\Prophecy\GameAnimationSample3.uproject" -WaitMutex -NoHotReload -NoUBA
```

5. Confirm the build ends with:

```text
Result: Succeeded
```

6. Reopen Unreal Editor.
7. Open affected Blueprints, use Refresh All Nodes if needed, then compile and save them.

## Verification

Check that the base DLL timestamp is newer than the last C++ API changes:

```powershell
Get-ChildItem "C:\Users\singerie\Documents\Unreal Projects\Prophecy\Binaries\Win64" `
  -Filter "UnrealEditor-GameAnimationSample3*" |
  Select-Object Name,Length,LastWriteTime |
  Sort-Object LastWriteTime -Descending
```

The important file is:

```text
UnrealEditor-GameAnimationSample3.dll
```

If only `patch_*.exe` files are newer, the editor may still load stale reflection data on startup.

## Recommended Workflow

Use Live Coding for:

- Editing existing `.cpp` function bodies.
- Small runtime logic changes.
- Quick tests during PIE.

Use a closed-editor normal build for:

- Adding, removing, or renaming `UFUNCTION` nodes.
- Adding, removing, or renaming `UPROPERTY` fields.
- Adding new `UCLASS`, `USTRUCT`, or `UENUM` reflected types.
- Changing function signatures used by Blueprints.
- Any C++ change after which Blueprints start showing red nodes.

## If It Still Fails

Do not start by deleting project folders. First check:

- Is Unreal Editor fully closed?
- Is Live Coding console fully closed?
- Did the command above run without `-LiveCoding`?
- Did `UnrealEditor-GameAnimationSample3.dll` get a fresh timestamp?
- Are the affected Blueprints compiled and saved after refresh?

Only consider cleaning `Binaries` or `Intermediate` as a last resort, and only with explicit user approval.

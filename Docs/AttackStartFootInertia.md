# Attack-start foot inertia

With optional [full-attack foot locomotion authoring](AttackFootLocomotion.md), inertia begins separately when each foot becomes attack-owned. A foot without authoring starts immediately at full entry; a pending foot starts its complete window at release. Releasing one foot does not restart the other's fade. Half-to-full starts the applicable foot handoffs; pure half entry still starts none.

**Set Attack Start Foot Inertia** (Prophecy / Agent / Feet) configures both feet independently of the existing pelvis node. Pins: Agent, Enabled, Translation Window Frames (default5), Translation Inertia (default1), Rotation Window Frames (default5), Rotation Inertia (default1). Off until configured. Zero strength or a window of0/1 bypasses that channel.

A new full attack samples the existing published foot transforms and adjacent world-space NN poses once. Their displacement/rotation supplies the entry velocity (one game tick is half the30Hz policy interval). Each active game tick retains that motion according to the strength and fades to authored motion by the selected deadline. No physical forces or NN outputs are changed. Pure half attacks start no foot inertia. Full-to-half and normal attack end preserve an existing fade; interrupted non-returning attacks, disable/reset/EndPlay clean up through the existing entry-inertia lifecycle. Repeated configuration calls do not restart a latched fade.

The common physical/render presentation path applies pelvis correction first, then foot correction. The existing bend-frame solve reconnects each knee while preserving hip position and segment lengths; unreachable ankle targets clamp to the leg's reach. Foot rotation carries the toe rigidly. Existing optional knee smoothing runs once afterward. A zero/finished translation channel leaves the current ankle position alone while rotation can continue. Pelvis and foot switches do not cancel each other.

Performance: no added timer, inference, full-pose sampling, or idle foot history. Both the pelvis and foot update paths return before sampling when there is no active entry, even if configured for the next attack. Entry seeding uses existing pose-store history; the pelvis can reuse its preceding active sample when still current. Finished foot entries/corrections are removed. Disabled pose paths only perform cheap guards.

Implementation: `ProphecyAttackStartFootInertia.inl`, included in the existing pelvis library; narrow `ReadBoneWorld` pose-store sampler. New focused automation: `Prophecy.NN.AttackEntry.FootInertia` and `Prophecy.NN.AttackEntry.PelvisRegression`. No Blueprint wiring is installed automatically.

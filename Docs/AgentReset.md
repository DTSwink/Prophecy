# Initial agent reset

Call **Initialize Agent Reset** once after the NN manager has initialized its agents and all agents have completed their delayed BeginPlay physics setup, before starting movement. `Agent Count` reports captured agents. Check `Return Value` / `Out Error`: calling before NN initialization is rejected and can be retried. Calling again after success keeps the original checkpoint.

Connect a key's **Pressed** execution pin to **Reset Initial Agents**. The request is queued once at the next timer boundary, so an input or hit callback cannot tear down a physics rig during its publication. Repeated requests before that boundary coalesce. Success means accepted; a later per-agent failure is reported in the Output Log.

Reset restores captured root location/yaw and the published lower/upper pose. It resets both previous/current NN pose histories, physical feedback history, interpolation tangents and all future roots. The window starts collapsed at the restored root. Linear/angular root momentum, movement input, both magic velocity sets, foot-pinning debug samples, hand/pelvis inertia history and the prepared balancing target are cleared. Attacks, defense and NN animation layers are stopped.

Reset also restores captured magnetization, feedback tolerance and inbound joint damping, including all walk/run and drawn/sheathed profile cells. It restores global magnetization enable/scales, body membership/gravity settings, lower-body tempering values, the physical mesh's material override and per-joint angular limits. The body-settings map remains sparse exactly as captured: a missing entry means native drive defaults for Jolt/HalfSim, not an explicitly disabled body. Explicit exclusions stay excluded. Running profile/snapshot-return blends, angular-limit blends, tempering returns and walk/run recovery blends are cancelled; their old destinations cannot overwrite the restored settings. Capture stores current blend values, not unfinished destinations. The private reset snapshot is separate from user-named profile snapshots.

The private physical-profile snapshot also captures locomotion, attack, parry and dodge clamps. Reset cancels pending clamp-return blends and restores their saved enable, leeway and inheritance flags. Reinitialize in a fresh Play session if the reset snapshot predates clamp support.

Root smoothing factors, inertia follow factors, interpolation mode and current simulation mode remain in place. Physical rigs are recreated at the restored pose, clearing their velocities and cached contacts/constraint impulses. Damping is staged while the rig is detached and applied to its replacement. Captured auxiliary primitive components on each agent (including the magic cube) return to their captured transforms with zero velocity through the Jolt-aware standard component API.

Equipment capture records whether the agent holds a sword, its class, and simulated/attached mode. Reset recreates that sword at the restored hand after the character rig is restored. It removes the currently held sword and the captured/reset-created copy if dropped, so repeated drop/reset cycles do not duplicate that item. A destroyed or hidden captured sword is recreated too. A baseline with no held sword restores empty hands. The replacement is a new actor, so external references to the old sword do not carry over. Other unrelated dropped/world swords are not swept up. This is event-only work, without a tick or polling path.

Only captured, still-existing registered agents are reset. Later spawns are excluded; destroyed agents/components are skipped. This is not a save-game restore: it does not reset arbitrary Blueprint variables, restart BeginPlay, undo Blueprint graph edits, or rewind custom timers. For example, reset `tick debug` yourself if your test logic uses it. A Tick graph that keeps issuing movement/impulses or new tuning commands will naturally resume after reset.

Capture must occur outside an attack/defense/animation layer. The external standalone Sim Bridge is unsupported and rejected; this reset operates on native UE NN agents.

No ongoing per-frame scan, tick component or timer. Capture allocates session-only snapshots; reset temporarily schedules a single callback. Snapshots are released on manager EndPlay/world cleanup. New native storage is separate from existing retained Live Coding allocations.

Implementation: `ProphecyAgentResetLibrary.*`, `ProphecyNNAgentReset.inl`, `ProphecyAgentResetPhysics.*`. A Play session initialized before the physics-reset patch must be started afresh to capture its baseline; reset rejects that missing baseline instead of silently capturing modified/dead settings.

The equipment extension likewise needs a new Play session after Live Coding: Initialize Agent Reset must capture the intended held sword and mode before it is dropped. Equipment snapshots use separate native storage to preserve the layout of existing physics snapshots during Live Coding. Scene testing is left to the user as requested; `Saved/Diagnostics/TestResetSword.py` is available for a bounded two-drop/reset plus destroyed-sword check, but was not run for this extension.

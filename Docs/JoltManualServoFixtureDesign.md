## Existing APIs and the implemented recording boundary

**Existing public native APIs are enough to execute the current Chaos callback.** `ConfigureNNPoseDataSource`, `ReadNNFutureWorldPose`, `SetSimulationMode`, `PublishManualFollowerSubstepTargets` and `ReleaseManualFollowerSubstepTargets` are already exposed on AProphecyAgent. The callback is allocated inside the real publication path when it finds a simulating component named PhysicalMesh and a live world solver (`ProphecyAgent.cpp:240`). Neither a Blueprint nor an NN manager nor a dedicated physical-animation target component is needed for this servo.

Important body-selection detail: the current CDO's `BodyMagnetizationSettings` has only nine lower-body entries. **The manual publisher can still target all 22 bodies.** It ignores the boolean return of `GetBodyMagnetizationSettings`; a missing entry returns default settings with simulate/magnetization=true and strengths 1 (`ProphecyAgent.cpp:299`, `:2845`). Ordinary RootAndJointTorque configuration instead treats a missing map entry as excluded. Preserve the nine-entry map for this CDO-derived fixture and verify that all 22 simulated PHAT bodies become targets. Do not insert a SetAllBodyMagnetization call merely to hide this contract difference.

The original gameplay APIs alone did **not** expose the immutable `FManualFollowerSubstepTargets` packet, its publication identity, exact worker invocation sequence, or replay of already-converted rigid-body endpoints. The added fixture-only [ProphecyManualServoCapture](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Public/ProphecyManualServoCapture.h>) interface now supplies that recording/replay boundary. Bone-space pose data alone is not sufficient for a sealed comparison: the Chaos publisher recomputes `BodyFromBone` from current body/socket state, which can diverge after the solvers produce different poses.

The implemented **opt-in, fixture-only record/replay facility at the existing packet boundary** observes packets before installation and lets replay install recorded packets after resolving stable body names to current handles. Retain its disabled ordinary-gameplay path and preallocated callback storage. It uses the existing Chaos callback and velocity-update code; it is a narrow native test hook, not a new production Blueprint API or another Chaos controller.

At each real PreIntegrate invocation, associate the consumed packet with a monotonically increasing fixture step index and record pre-servo X/R/V/W and post-servo V/W. Store fixed-size/preallocated POD in the callback; flush/report on the game thread after the case, with overflow or missing step an explicit failed capture. Do not log, serialize JSON, access UObjects, resize arrays or acquire additional engine locks from the solver thread. Preserve the existing TargetLock boundary when reading the packet. A separate unrelated callback is insufficient to prove ordering around this callback's velocity writes.

For the first synchronous, one-step-per-frame fixture, enforce one PreIntegrate invocation per recorded frame and integration dt=1/60. The callback's general `GetDeltaTime_Internal` field is not assumed to be every internal substep's integration interval: for later substepping coverage, instrument/verify the actual evolution PreIntegrate dt supplied by UE rather than infer it from the game-frame dt. Record both actual integration dt and the distinct servo denominator described below.

A capture includes:

| Immutable input | Required content |
|---|---|
| Provenance/header | Source/DLL/mesh/PHAT/cook hashes, engine/Jolt versions, frame and unit conventions, skeleton order, case settings, initial world origin, gravity/material/collision/solver settings, exact overrides versus the CDO |
| Pose publications | Publication index, 30 Hz policy index, local and previous/current component poses/world carriers, SourceTimeSeconds, frame world time/dt, interpolation flag/alpha, body selection and strengths, rigid-forearm flag |
| Final target packets | Stable body name/rig index, actual bone world transform used, BodyFromBone transform, final target body position/quaternion, effective nonnegative linear/angular strengths, packet sequence and published MaximumSubstepSeconds |
| Per-step consumption | Step/frame/substep index, packet sequence, actual integration dt, denominator h, controller-enabled/active state and the packet's exact immutable body targets; initial/explicit external impulses with units and application stage |
| Outputs kept separate | Pre/post servo state, completed-solver body/mass states, constraint/contact observations and error metrics; these are results, not next-step target inputs |

Write the capture once with no overwrite and a content hash. Reject missing/duplicate/unordered steps, missing body mappings, nonfinite transforms, zero quaternions or packet-count mismatches. The existing publisher returns early on a failed pose read without necessarily clearing its old packet; the fixture should fail that capture, not silently record it as a new target or change production stale-target behavior.

Replay the sealed input in separate fresh backend cases. Chaos replay injects the sealed packet into the existing callback; Jolt consumes the same packet with converted units. Both start from the same recorded state and external-event schedule. Do not regenerate a replay's final endpoints using its own current mesh/socket state. Input integrity remains required; repeat Chaos trajectory measurements are diagnostics, not a gate on the functional Jolt adapter. Detailed recording and disk output stay outside timing; use replay for repeated diagnostic timing and retain total integration costs separately from controller/solver costs.

## Retained controller formula, rigid frames and denominator

Current callback source: [ProphecyAgent.cpp:111](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyAgent.cpp:111>). For each eligible body:

```text
h = max(published MaximumSubstepSeconds, UE_SMALL_NUMBER)
if L > 0: V' = V + ((TargetPosition - X) / h - V) * L
if A > 0:
    dq = normalize(TargetRotation * inverse(R))
    if dq.w < 0: dq = -dq
    axis, angle = dq.axis_angle()
    W' = W + (safe_normal(axis) * angle / h - W) * A
```

The published h is `max(epsilon, min(frameDt, MaxSubstepDeltaTime))` if project substepping is enabled, otherwise `max(epsilon,frameDt)` (`:289`). Targets remain the same packet across the frame's solver invocations. **Do not replace h with Jolt step dt when the two differ.** The no-substepping 1/60 case intentionally makes them equal; a later fixed 1/30 frame split into two 1/60 steps, followed by a non-divisible frame/substep case, must validate the distinction.

L/A are clamped only at zero during publication, not at one. Zero skips that rewrite; fractional values blend the current velocity toward the target velocity; values above one extrapolate. The Chaos callback does **not** inspect bCancelGravity, apply force/torque, divide by mass, use physical-animation gains/force caps, set transforms, or implement the WorldOneStep gravity subtraction. The Jolt adapter retains this target/h/strength calculation and body-origin error, then uses its native clamped velocity setters. Those Jolt velocity caps are an intentional backend behavior, not a claim that Chaos applies the same clamp at the same stage. Validate zero, fractional and unit strengths in bounded diagnostic cases; keep their inputs identifiable in performance reports.

The endpoint conversion is existing code, not a proposed new approximation:

```text
ActualBoneWorld = PhysicalMesh.GetSocketTransform(Bone, World)
BodyFromBone = Body.GetUnrealWorldTransform().GetRelativeTransform(ActualBoneWorld)
TargetBodyWorld = BodyFromBone * InterpolatedWorldBoneTarget
```

Store all three transforms at publication. UE `GetUnrealWorldTransform` can include its custom projection callback (`BodyInstance.cpp:2706`); record whether a custom projection is bound, and separately sample raw callback X/R. Do not assume a projected game-thread transform equals raw solver state for every future rig.

Also export shape-local transforms, body-to-bone offsets, body world frame, **mass/COM world and body-local frames**, mass, full principal inertia plus its orientation, and linear/angular velocities. Chaos integrates COM position/orientation with V/W after this callback (`PBDRigidsEvolutionGBF.cpp:955`), even though this callback forms position/orientation error from raw X/R. Jolt exposes both body-origin `GetPosition()` and `GetCenterOfMassPosition()` ([pinned Body.h](https://github.com/jrouwe/JoltPhysics/blob/e77f175595e64cb44218cc9d9d56fc365ad0e36a/Jolt/Physics/Body/Body.h)). The original fixture intentionally copied the body-origin error directly into COM velocity. This historical restriction was superseded by the user-approved 2026-09-11 hand-drift correction: the requested origin velocity now includes the angular-cross-COM term when converted to COM velocity. Matched scene measurements and offset-body tests establish the reason and coverage; see `Docs/JoltHandDriftInvestigation.md`. This is a deliberate controller correction, not an exact Chaos-formula parity claim.

The Jolt adapter converts cm→m, cm/s→m/s and kg·cm²→kg·m²; angular velocities stay rad/s. Reuse the integration's declared axis/quaternion conversion and validate it with explicit axis rotations and an offset body; do not invent a coordinate reflection or apply a quaternion component swap without that contract. Each Jolt body needs the same physical mass/inertia representation, including COM/principal-axis orientation, not just numerically similar shape dimensions.

The implemented adapter uses one [FVelocityServo](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Plugins/ProphecyJolt/Source/ProphecyJolt/Private/ProphecyJoltVelocityServo.cpp>) listener for the fixture body set. Before synchronous `PhysicsSystem::Update`, `PrepareActivation` computes candidate velocities for sleeping targets using the same retained formula and denominator. It tests enabled channels with **Jolt's native `Vec3::IsNearZero` in native units**, releases all read locks, and activates the required bodies through the ordinary BodyInterface. This includes them in the first gravity/force/damping pass. It does not reproduce Chaos's componentwise UE-unit `IsNearlyZero` thresholds, wake every body every frame, or temporarily widen velocity caps.

During each collision step, `OnStep` recomputes the rewrite against that step's current body state and calls **`SetLinearVelocityClamped` / `SetAngularVelocityClamped`**, preserving each body's configured native caps. It uses no-lock body access while Jolt holds its update locks; it neither accesses UObjects nor allocates worker storage or adds/removes bodies. Invalid/non-dynamic handles, nonfinite/overflowing rewrites and an unexpectedly sleeping target that still requires native wake remain errors. The earlier proposed rejection based on a disagreement with Chaos's tiny-velocity threshold is obsolete. Jolt-native activation and clamping are the chosen functional behavior.

Pinned scheduling still matters: registered listeners run with no active bodies (`PhysicsSystem.cpp:191`), despite the header comment. Listener-time activation is allowed, but the first active-body list has already been captured, so such bodies miss that collision step's gravity/force/damping pass. Pre-Update preparation avoids that delay in this synchronous immutable-target fixture. Jolt evaluates rigid-body sleep only on the last collision step. These source facts explain the chosen scheduling; they do not establish equivalent Chaos sleep or force integration. See [PhysicsStepListener.h](https://github.com/jrouwe/JoltPhysics/blob/e77f175595e64cb44218cc9d9d56fc365ad0e36a/Jolt/Physics/PhysicsStepListener.h) and the current [world Step path](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Plugins/ProphecyJolt/Source/ProphecyJolt/Private/ProphecyJoltWorldSubsystem.cpp>).

## Articulation and collision acceptance boundary

Capture **all 21 actual valid joints** after manual entry/warmup: bone endpoints, complete live profile, child/parent reference frames and rotations, linear axes/limits, angular axes/angles/soft stiffness/damping/contact distance/restitution, motors, projection/mass conditioning, and relevant Chaos conversion/solver overrides. Export authored shape topology and the 47 disabled collision pairs with stable IDs. Verify whether helper transition code or asset recreation changed live frames before freezing the input. Never reconstruct constraint frames solely from guessed skeletal bone pivots.

The CDO-derived manual entry preserves authored angular limits. It must not inherit the old native FullSim Limited179° override or HalfSim's all-Free state. Fresh authored PA_UEFN has 21 soft-limited swing joints and 13 soft-limited twists plus eight Locked twists, and the named Free profile is not uniformly free. Snapshotting confirms the actual fixture; do not simply stamp those expected counts into the report.

**Accepted angular-limit decision, 9 September 2026:** the user selected **hard Jolt angular limits at the original PHAT angles, with no retuning**. Custom soft angular constraints are deferred. Retain all authored Limited/Locked/Free axes and angles; do not replace the rig with all-Free or Limited179 constraints. Keep the Chaos reference unchanged and export its effective soft settings, so the intentional hard-versus-soft difference remains visible in comparisons. Stock Jolt's missing soft-angular facility is therefore no longer a prerequisite for this approved hard-limit fixture. Chaos conditioning/projection still needs an explicit mapping or a reported unresolved behavior; do not silently change it. An isolated-body servo check remains useful but does not replace the complete 22/21 articulated fixture.

Use two explicit collision cases, each in a fresh state:

| Case | Required physical interaction |
|---|---|
| Air servo isolation | No gravity; keep rig/body physics created but disable external/self/crowd contacts through explicit filters. Capsule and inherited/debug meshes have no physical interaction. Anatomical joints remain active and unchanged. This isolates the servo/articulation, not a free collection of bodies. |
| Floor with gravity | Native box top at z=0, dimensions/material/friction/restitution recorded, static WorldStatic; dynamic PHAT shapes interact with floor only. For both, export exactly **32** actual channel responses plus resolved final per-shape filter data. Raw BodyInstance responses are not sufficient to prove the effective pair rule. Preserve disabled-pair provenance and report material values and combine policy; the current native Jolt contact response need not match Chaos 1:1. Report the deliberate floor-only override of the CDO's broader matrix. Floor-only does not validate self/crowd/sword collisions. A later scheduled perturbation should record whether it is Δvelocity, linear/angular impulse or force, and its timing relative to the servo; the existing benchmark's `AddImpulse(...,true)` is not mass-scaled impulse evidence.

Require finite state, correct body/joint/packet counts and valid initial-state/input provenance. Record per-step controller and completed-physics differences for diagnosis without converting small Chaos trajectory differences into a migration gate. Functional validation must instead demonstrate that the articulated character follows targets, handles the selected contacts and publishes a complete physical pose to rendering and actual feedback. The new live benchmark's 0.02 cm / 0.02° checks compare **the same completed Jolt pose across feedback and skeletal sockets**, not Jolt against Chaos. Those checks are awaiting runtime validation; they are not a global gameplay-error budget. Compare intermediate frames as well as final state.

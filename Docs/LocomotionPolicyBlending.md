# Walk/run lower-body blending

On **Prophecy Agent**, call **Set Locomotion Policy Blend Times** once with independent **Walk To Run Seconds** and **Run To Walk Seconds**. For example, 0.2 and 0.35. **Get Locomotion Policy Blend Times** reads them back.

Defaults are 0/0, preserving immediate policy switching. Durations use simulation time, so game slow motion slows the transition too. Negative/nonfinite inputs fail without changing either setting. Nonzero duration changes configure the next transition; setting the active direction to zero ends it on the next NN step.

**Get Locomotion Checkpoint Weights** returns **Walk Weight** and **Run Weight** in the latest published 30 Hz lower-body prediction. Each is 0..1 and together they equal 1. It reads existing state only; it does not evaluate an NN or copy the pose. Before registration it returns false and zero outputs. These are policy weights, not percentages of a physical pose; full attacks may hide the underlying locomotion pose.

**Set Locomotion Walk Checkpoint Speed Threshold** chooses the walk checkpoint when actual horizontal mover speed is strictly below the supplied value in **cm/s**, even while run mode is selected. Default **-1** disables the override; negative inputs normalize to -1. **Get Locomotion Walk Checkpoint Speed Threshold** reads it back. For example, 250 selects walk below 2.5 m/s and run at/above that speed while run mode remains selected. Walk mode always selects walk. This changes only checkpoint selection, not run intent, movement speed or the future root window. Threshold crossings use the same directional blend times; there is no hysteresis. The selection check uses squared planar speed at the existing NN step, with no extra Tick, velocity queries or square root.

The existing Run input still chooses the gait. During a transition, both lower-body checkpoints predict from the shared current/previous lower-body history. Each prediction receives its own foot pinning, roll and floor correction, then their positions/toes blend linearly and rotations use shortest-path quaternion interpolation, with a smoothstep blend weight. This includes **pelvis position and rotation**, both thighs, feet and toes; calf rotation is reconstructed using continuously blended hinge calibration from the two training contracts. The blended state becomes the next lower-body history; the upper-body checkpoint remains unchanged and receives the resulting pelvis base normally.

Reversing gait during a transition starts from the current mixture and uses the new direction's full configured duration. Full attacks bypass/reset the gait blend; half-attack legs retain locomotion blending. This does not blend root movement speeds or change the mover's acceleration rules.

Outside transitions, no second inference, second pinning correction, pose blending loop, timer or additional Tick runs. The existing NN loops retain a small state check. During transitions both policy batches may run (the current models use fixed batch sizes), and only blending agents receive the extra pose correction/interpolation. No performance benchmark was requested or run. Ordinary 30 Hz pose presentation interpolation still applies.

Pinning debug values during a blend are the weighted per-policy values; blended raw logits combine different checkpoint conventions and should not be interpreted as one policy's probability. Blending poses can introduce transient foot sliding; this is a policy crossfade, not a new world-space foot lock.

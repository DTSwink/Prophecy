# Root pelvis bounds

Blueprint node: **Set Root Pelvis Bounds** (Agent, Enabled, Radius Cm, Magic Cube). The radius pin defaults to **20 cm**. Call once to enable or change it; call with Enabled=false to disable. The feature is off until configured. **Get Root Pelvis Bounds** returns its current configuration.

Connect the Magic Cube component reference to register it. Whenever bounds successfully translate the root/window, the cube receives exactly the same world offset, preserving its orientation and linear/angular velocity. Its pre-move location is captured so an attached component does not move twice. The existing Jolt adapter synchronizes the native body through TransformUpdated; Chaos uses TeleportPhysics. The optional pin defaults to None, which clears a previous cube registration. Weak references do not keep destroyed components alive. This registration applies to automatic pelvis-bounds corrections, not unrelated manual placement calls.

For a simulated pelvis, the automatic check runs after locomotion root presentation each frame. It projects the physical pelvis onto the root's horizontal plane. A root outside the selected circle moves to the nearest point on that circle; a root already inside it is untouched. Radius0 places the root directly below the sampled physical pelvis. Negative/nonfinite radii are rejected without replacing the previous setting.

The correction uses a pose-preserving branch of the root placement implementation. It translates current/previous roots, published root history, input-window origin/future world roots and mover position by one common offset. Root-relative window shape, orientations, velocity and magic velocities are preserved. Lower and upper recurrent frames, publication frames and retained physical feedback history are rebased into the translated root frame; upper base/pelvis features are rebuilt. Cached world-space NN body targets and half-attack visible world poses stay in place. Character Jolt bodies are not teleported; only the optional registered cube is. Root Z does not change. This is a planar bound, not a solution for upward NN pelvis drift.

The pose-preserving behavior fixes the moving-target loop documented in RootCubeBoundsRunawayDiagnosis.md: bounds must not move the NN pelvis target away while attempting to bring the root closer to the physical pelvis. The existing explicit Set Locomotion Root Window Location Blueprint node retains its original whole-pose placement behavior; automatic bounds opt into recentering instead.

Same locomotion ownership rules as the existing placement node: full attacks, NN defense, external bridge and disabled inference retain their existing root handling. Half attacks may be corrected. A nonsimulated pelvis is skipped: translating an entirely kinematic character would move the pelvis together with the root and would not constrain their separation.

Disabled settings consume no pelvis sampling or per-agent component/tick work. The manager performs one empty-map check when no agent has enabled it. Enabled entries alone are visited; only actual out-of-circle corrections invoke window translation. Corrections are collected before actor movement so overlap callbacks can safely retune the feature. Weak entries are cleaned and manager EndPlay removes its agents. Configuration survives the existing motion-reset operation.

Implementation is in an independent CPP to keep future feature edits from recompiling the full NN manager. Native test: `Prophecy.Root.PelvisBounds.PlanarCircle` (inside, boundary, diagonal circle, zero radius, preserved height, invalid radius). Build/install verification is recorded in the project journal.

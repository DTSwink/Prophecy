# Standard force nodes with Jolt

`UProphecyPhysicsSkeletalMeshComponent` and `UProphecyPhysicsStaticMeshComponent` override Unreal's existing virtual physics methods. Existing Blueprint nodes keep their names and pins. When the receiver is owned by a live Jolt character/body component, they address its native bodies; otherwise the same call uses the engine's Chaos implementation. There is no per-frame polling or global UFunction hook.

Implemented calls: Add Force, Add Impulse, Add Torque and Angular Impulse (radians and the existing degrees wrappers), Add Force at Location, Add Force at Location Local, Add Impulse at Location, Radial Force/Impulse, Set Physics Linear/Angular Velocity, and Set All Physics Linear/Angular Velocity. The skeletal component also implements Add Force/Impulse to All Bodies Below.

Units and selections match the UE API: centimetres, kilograms, seconds; angular velocity/acceleration in radians (degrees wrappers convert); physical torque/angular impulse in kg*cm² units. Accel Change ignores mass/inertia; Vel Change directly changes velocity. At-location inputs use world coordinates, except the explicitly local force node, which transforms both force and position through the physics body's origin/rotation. None addresses the UE root physics body for single-bone calls. Below-bone calls respect Include Self and can begin at a non-PHAT skeletal helper bone. Invalid bone names do not silently act on the root.

Skeletal radial physical forces/impulses are distributed by each body's fraction of the total rig mass, matching `USkeletalMeshComponent`. The mass-independent variants apply the specified acceleration/velocity change to each affected body. Radius, constant/linear falloff and Ignore Radial Force/Impulse are honored. Bodies are sampled at their native centres of mass.

Forces/torques accumulate for the next shared Jolt Update and are cleared by Jolt afterward; call them each gameplay tick for continuous force. Impulses and velocity setters act immediately on native velocity. Existing physical-animation drives continue to act and can oppose these changes. Native speed limits remain in force. No backend or simulation-mode toggle is implicit. Invalid/non-finite/overflowing native commands are rejected before writing body state.

The dispatch requires these component subclasses. Plain engine components elsewhere are not globally modified. `Prophecy.PhysicsReceiver.Upgrade <BlueprintPath> <SCSComponentName>` upgrades one plain skeletal/static mesh template, backs up both its saved asset and currently loaded revision, retains its component name/properties and verifies graph wiring before saving. It refreshes inherited Blueprint pin types and compiles before saving; errors or wiring changes roll back the upgrade. It refuses PIE and components already containing custom subclass behavior.

Scope: these force/velocity setters do not change the standard nonvirtual velocity getters, mass setters, simulation toggles, sleep nodes, overlap events, or static-world import policy. UE collision/query receivers remain Chaos-query-only while Jolt owns simulation.

Skeletal rigs now apply authored inertia conditioning at admission; physical angular forces/impulses use that effective native inertia. Accel Change / Vel Change retain their mass-independent meaning. The retained UE query body's inertia getter reports raw properties; see [JoltFeedbackHandDrift.md](JoltFeedbackHandDrift.md).

Installed assets (2026-09-11): `BP_ProphecyManualPoseAgent.PhysicalMesh` uses the skeletal forwarding class; `A_Sword.sword` uses the static forwarding class. Both upgrades compiled, saved and verified unchanged graph wiring. Backups are under `Saved/Diagnostics/ForceNodes/Backups/20260911-090533` and `20260911-090534`. Existing nodes targeting these components need no rewiring. For new props, use `Prophecy Physics Static Mesh Component`; arbitrary plain engine meshes are outside this dispatch.

Validation: four focused automation tests passed with zero errors/warnings: `PhysicsCommands.UnitsMassInertiaAndLifetime`, `PhysicsCommands.StandardSkeletalNodesAndChaosFallback`, `BodyComponent.SharedStepQueryAndCleanup`, and `Character.RuntimeBoneMaterials` (all under `Prophecy.Jolt`). They cover native force/impulse unit conversion, mass/inertia, local/point forces, velocity setters, wakeup, invalid/stale input rejection, inherited Blueprint dispatch, bone/below/radial selection, degrees wrappers and Chaos fallback. The initial Chaos fallback assertion incorrectly expected an externally queued impulse to appear immediately in solved velocity; the corrected check verifies the actual Chaos queued impulse delta. No production fallback change was needed for that test correction.

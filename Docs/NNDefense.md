# NN defense integration

Current live delivery: the saved **upper-only parry**, checkpoint 770015, and **full-body dodge**, checkpoint 198044. Both are installed in the normal Editor build; the latest private batching/policy-handoff refinement is installed through Live Coding.

Blueprint nodes on `ProphecyNNDefenseLibrary`:

- **Start NN Parry**: Agent (defaults to Self), Attacker, Blocker (Blade / Left Arm / Right Arm), Maximum Duration Seconds (default 3), Out Error. Trigger the attack first. Both agents must belong to the same initialized 30 Hz manager. Blade blocking requires a held sword. A defender cannot simultaneously own an attack or animation layer.
- **Start NN Dodge**: Agent (defaults to Self), Attacker, Maximum Duration Seconds (default 3), Out Error. Same manager/attack prerequisites. Captures the defender's current walk/run category for the episode, owns the full pose and reference root command, and uses the saved six control banks. Starting either defense replaces an existing defense with fresh history.
- **Stop NN Defense**: releases the active defense's pose ownership. Does not stop the opponent's attack.
- **Get NN Defense Status**: reads the completed result, including step count, consumed attacker frame, block/harmful contact, fractional contact time and collider. It does not perform inference, sweep, or read physics bodies.

The manager completes lower locomotion, then completes the attack, then batches active parries. It sends only the attacker's completed previous/current samples. Target and initial root displacement/yaw are captured once. Parry carries its own upper history; rendered/interpolated bones are not recurrent input. Completed locomotion pelvis and leg transforms are retained, including the agent's existing locomotion clamp settings. Parry upper transforms use the saved decoder and baseline transport, without the locomotion hand/forearm presentation clamps.

One lazy CPU model/geometry set is shared per manager. Only agents started through the node allocate defense history. Inactive agents gain no component, timer, or extra NN call. The existing fixed-width locomotion model remains fixed-width; inactive lanes in a running locomotion batch are not advertised as pruned. Parry's additional network batch contains active prepared defenders only. Model assets and geometry are staged through `GameAnimationSample3.Build.cs`.

Dodge runs after completed attacks too. It groups active defenders into walk/run lower batches, followed by one upper batch, with reusable buffers and no normal locomotion encode/cleanup for those lanes. It keeps the original 13 defender colliders and uses the attack hit event for conditioning. Its private recurrent root advances independently of presentation interpolation; stopping transfers the completed lower/upper history back to locomotion. The continuous locomotion-window getter returns false while full-body Dodge owns the root. Physical feedback is not injected into its private recurrence.

Contacts use the saved training OBB attachments, forearm cross-section override, strict continuous sweep and blocker-before-harm rule. An unresolved search never grants a block. Contact ends the defense after publishing that completed pose; the next step resumes locomotion. Explicit stop, opponent end/restart and duration also end it. Status remains readable until another defense replaces it. These are NN target-pose contacts, not Jolt physical-body hit events.

Current limitations: the live attack source uses the existing managed attack's sword/anatomical collider. Pike is supported as a sword thrust using the same blade box as slash, matching the original harness. Synthetic spear needs a separate projectile source. Physical target following retains existing agent settings. A predicted parry is not a guaranteed successful block from arbitrary live initial conditions.

# NN defense integration

Current live delivery: the saved **upper-only parry**, checkpoint 770015, and **full-body dodge**, checkpoint **205525** (fine-tune installed 2026-09-17). Both are installed in the normal Editor build; the latest private batching/policy-handoff refinement is installed through Live Coding.

Blueprint nodes on `ProphecyNNDefenseLibrary`:

- **Start NN Parry**: Agent (defaults to Self), Attacker, Maximum Duration Seconds (default 3), Out Error. Trigger the incoming attack first. Both agents must belong to the same initialized 30 Hz manager. Before the attack NN outputs Armed, a successful call only queues the request: the defender retains normal locomotion/attack ownership, and no defense inference starts. The two completed defender poses are retained while waiting. On Armed, defense takes over (interrupting its own NN attack if necessary). An authored animation layer still prevents activation.
- **Start NN Dodge**: Agent (defaults to Self), Attacker, Maximum Duration Seconds (default 3), Out Error. Same Armed gate and prerequisites as Parry. It owns the full pose, follows the live walk/run category and mover window, and adds learned root corrections using the saved six control banks. Starting either defense replaces an existing defense with fresh history.
- **Stop NN Defense**: cancels a waiting request or releases active defense ownership. Does not stop the opponent's attack. Stopping/replacing the incoming attack also cancels its waiting requests, including replacement with the same attack family.
- **Get NN Defense Status**: reads the completed result, including step count, consumed attacker frame, fractional contact time and collider (no block/harm classification). It does not perform inference, sweep, or read physics bodies.

While waiting for Armed, status succeeds with Active=false and CompletedSteps=0. Maximum Duration starts at activation, not at request time. The gate reads the actual attack output latch (not elapsed frames or a guessed preparation time). It initializes from the two preceding completed poses and generates the first defense output on the Armed policy frame itself. Pending activation failures are logged. With no requests there is only an empty-container check, no agent scan or extra network evaluation. The waiting state is outside retained manager allocations, so this change requires no layout migration or Blueprint edits.

The manager completes lower locomotion, then completes the attack, then batches active parries. It sends only the attacker's completed previous/current samples. Attack target and root movement conditioning are refreshed each policy step without resetting defense history. Parry carries its own upper history; rendered/interpolated bones are not recurrent input. Completed locomotion pelvis and leg transforms are retained, including the agent's existing locomotion clamp settings. Parry upper transforms use the saved decoder and baseline transport, without the locomotion hand/forearm presentation clamps.

One lazy CPU model/geometry set is shared per manager. Only agents started through the node allocate defense history. Inactive agents gain no component, timer, or extra NN call. The existing fixed-width locomotion model remains fixed-width; inactive lanes in a running locomotion batch are not advertised as pruned. Parry's additional network batch contains active prepared defenders only. Model assets and geometry are staged through `GameAnimationSample3.Build.cs`.

Dodge runs after completed attacks too. It groups active defenders into walk/run lower batches, followed by one upper batch, with reusable buffers and no normal locomotion encode/cleanup for those lanes. It keeps the original 13 defender colliders and uses the attack hit event for conditioning. Its private recurrent root advances independently of presentation interpolation; stopping transfers the completed lower/upper history back to locomotion. The continuous locomotion-window getter returns false while full-body Dodge owns the root. Physical feedback is not injected into its private recurrence.

Kinematic contact stops use the pose-reference mesh's actual PHAT simple shapes and the held sword's simple collision, swept through translation and rotation between completed policy poses. No training enlargement is applied to stop geometry. The earliest confirmed contact ends defense regardless of the contacted limb; there is no selected blocking arm or success/damage classification. Contact ends defense after publishing that completed pose; the next step resumes locomotion. Sim/HalfSim leave contact stopping to gameplay Hit events. Explicit stop, opponent end/restart and duration also end defense. Status remains readable until another defense replaces it. These kinematic geometric queries do not create physical bodies or emit Hit events.

The live attack source uses a separate training attacker catalog: raw forearm attachments for punches, calf attachments for kicks, head, and the hand_r blade for pike/slashes, with reference size scaling. Defender-specific thinning/reconstruction never defines the attack input. Synthetic spear needs a separate projectile source. Physical target following retains existing agent settings. A predicted parry is not a guaranteed successful block from arbitrary live initial conditions. See [DodgeHookLViewerMismatch.md](DodgeHookLViewerMismatch.md) for the corrected input/timing fixes, physical contact stopping, and exact Python/native replay evidence.

## Parry completion on Hit (2026-09-17)

Parry ends on the incoming attack's first learned **Hit** output, using the existing locomotion handoff immediately in that same policy step. It does not continue through the attack's recovery tail, and does not require a physical collision. Earlier contact/explicit stops still apply. Requests made after Hit are rejected; a queued Parry cannot activate after Hit. Dodge has its separate configurable post-Hit delay described below. Six current-scene trials across both demo roles verified same-frame release.

## Dodge delay after Hit (2026-09-17)

**Set Dodge Frames After Hit** takes Agent (the defender) and Frames (default1). **Get Dodge Frames After Hit** reads it back. Counts attacker NN policy frames at30Hz, not render/game Tick frames: if Hit first appears on frame15, values0/1/3 release Dodge on frames15/16/18 respectively. Default1 applies even if the setter is never called. Negative values are rejected; setting1 removes the per-agent override. Changes affect an ongoing Dodge on its next policy step. Settings are cleared with the agent.

Uses the latched first Hit frame, so repeated Hit outputs do not restart the countdown. Release uses the existing locomotion/root handoff before another Dodge inference on the expiry step. New Dodge requests at/after that deadline are rejected. Earlier PHAT contact (kinematic only), explicit stop, attack end/replacement, maximum duration and existing lifecycle/error rules still apply. No timers, actor scans or additional work outside active defense; the delay lookup runs only after Hit. Parry remains immediate on Hit.

Verified eight current-scene episodes at delays0,1,3 with exact Hit+X locomotion transitions. Getter defaults/per-agent isolation/negative rejection passed. See `Saved/Diagnostics/DodgeHitDelay/summary.json`. Installed through Live Coding; no restart or Blueprint/map authoring changes.

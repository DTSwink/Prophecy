# Upper-body exit inertia

`Set Attack Upper Body Inertia` includes both arms and hand translation, in addition to the ten FK core rotations. The **Hand Inertia Space** pin chooses **Root Local** (default: NN locomotion root position and heading) or **Spine Local** (`spine_05`, including its tilt after core inertia). Response, Hold, Blend To Normal and Momentum retain their existing meanings. Configure the space before or at special end; changing configuration during a return cancels that return, as before.

At the end of a special, each outgoing arm pose is expressed relative to its own sample's reference frame before measuring hand linear and upper-arm/forearm/hand angular velocity. Reference movement is therefore not counted twice. These springs advance in the selected local space, then map through the current root or spine frame for the reachable two-bone solve. Core spine/neck/head/clavicle angular inertia retains its existing behavior. During locomotion, the ordinary upper checkpoint supplies the destination pose; core inertia modifies the torso, then arm inertia runs after hand recovery, tempering, ordinary hand inertia and neutral return. Accepted arm transforms feed upper recurrence and publication. World-space publication caches do not determine the inertia reference space.

Hold retains inertia ownership; the spring still evolves. Blend uses smoothstep to transfer ownership to the current normal controls. A very large Response weakens the spring's damping and attraction, so long holds can still produce large motions. Momentum multiplies the captured outgoing velocities. An unreachable hand trajectory is projected to the reachable arm and outward velocity is removed; physical reach constraints necessarily limit exact velocity continuity.

The outgoing forearm length is retained during Hold and blended toward the configured locomotion forearm/hand clamp range during Blend. This avoids immediately shortening an attack arm before the first inertial step can be shown. Publication uses cached accepted world arm endpoints, including the actual outgoing endpoint for the first interval; it does not apply the old hard forearm clamp a second time. Normal clamp ownership resumes at retirement. Lower-body ownership is unchanged.

Arm storage is a separate sparse sidecar, preserving retained Live Coding layouts. It shares the existing upper-inertia clock and lifecycle. Disabled, zero-duration, canceled and retired states allocate no arm state and do no arm spring, IK or pose-cache work; only an empty-state guard remains. Active work is bounded to two arms per NN update. No additional checkpoint inference is introduced.

# D/S Sword Holster Lab

Open **D-S Sword Holster Lab** on the Windows desktop. The teal D/S sword icon launches its own window and local service at `http://127.0.0.1:8818`. Unreal is not required to run the lab. The original Attack Recovery Lab and its saved state are untouched.

**D/S** means **drawing (unsheathing) / sheathing** in this project.

## Controls

- Choose **Idle** or **Walk forward · in place**, then **Sheathe** or **Draw / unsheathe**.
- **D/S start tick** schedules entry; one authored second is60 ticks. The timeline supports any start point, playback, seeking and single-tick stepping.
- Playback ends at D/S completion if earlier than **Timeline length**, including FK return, drawing unshrink and any remaining head look-out. The timeline, End button, stepping and .35s loop pause use that endpoint; pose and base-motion ghost freeze there. Stalled or unfinished actions retain the configured limit. The configured length remains saved, so changing parameters can lengthen the action again. `node test_duration.cjs` verifies completion and transport behavior.
- **FK return controls →** opens a separate panel on the right. It shows the selected action’s independent return profile, saved for Drawing and Sheathing separately; panel open/closed state also persists. Return starts exactly at slide completion. Return time, easing and main inertia are visible; method/space/hold/decay/spine-angle extra time/twist removal and per-bone weights are under expandable sections. Defaults reuse the previous lab: enabled,1s, easing1, inertia1, hold0, decay1, parent-local, blend+inertia, extra.29s/90°, twist removal0, bone weights1.
- **Draw Sword** exposes the Unreal Sheathe direction, Max Reach Speed (cm/s), Max Reach Rotation Speed (degrees/s), and Sliding Speed (cm/s).
- **Drawing / Sheathing timing curves** shows only the selected action’s pair: **Reaching** and **Sliding velocity**. Drawing and sheathing each keep an independent pair (four curves total). Each starts linear with four draggable interior points and fixed0→1 endpoints. Horizontal position is time within that phase; vertical position is recorded phase progress. Steeper sections play faster; flatter sections play slower. Release a point to apply; **Linear** resets only that curve. Editing or resetting preserves playback: running stays running, paused stays paused. Body/arm planning is reused; only the time map and independently clocked head track are refreshed. All four persist across action switches, refresh, saved settings, snapshots and JSON import/export.
- **Spine / clavicle reach** adds two lab controls: **Angle limit** (45° default, shared per joint) and **Max angular speed** (90°/s default, applied independently to each added turn). Spine twist only; clavicle has two swing axes with no rotation around its own length. Clavicle turning around world Z remains available. Setting the limit to0 restores the original arm-only solve.
- **Head look** replaces the old head correction control. **Look-at alpha** defaults1:0 keeps original forward facing,1 aims directly at the holster entrance, intermediate values partially look toward it. **Max look-in** and **Max look-out** are separate angular speed limits, both default180°/s. Independent **Draw threshold** .3 and **Sheathe threshold** .5 start the forward return at30% of the outward slide and50% of insertion respectively;0 means slide start,1 means slide end. **Look-in exponent** and **Look-out exponent** independently shape the turns:1 preserves the current motion; higher values (up to8) give a slower start and finish with a faster middle. Both default1. Stronger easing can take longer because the maximum speeds still apply. All seven controls persist with settings, snapshots and JSON.
- **Set Sword Holster Profile** exposes Shrink Percent and Unshrink Duration (authored seconds).10% is10% shorter along the blade axis only. Initial tuning matches the current Unreal node:35%, .5s,100/180/60, start25.
- **Holster placement** provides XYZ and Pitch/Yaw/Roll offsets from the imported pelvis-relative reference. Values use Unreal local axes and cm/degrees. Zero restores the imported placement. The seated sword reference follows the holster.
- Readouts show hand-to-target distance, reach shortfall, retained blade scale and insertion percentage. Reach-limited poses remain stalled, matching the current algorithm's lack of a fallback; the lab does not silently increase shrink or loosen arrival tolerances.

Space plays/pauses; arrows step one60Hz tick and wrap; P saves a snapshot. Drag orbits, right-drag pans, wheel zooms, double-click resets the camera. View contains upper-body/pelvis visibility, full body, skeleton, base-motion ghost, arm rotation gizmos and **Two-colour limbs** (on by default). Cyan longitudinal halves follow each upper/lower arm and thigh/calf rotation; the markers are visual only. Playback loops with a .35s inspection pause. Input changes commit on change/release, not during slider dragging.

Space and left/right arrows belong exclusively to playback even while an input, dropdown, slider, checkbox or button is focused. Their press/release events cannot reach other lab controls or trigger native widget actions. Holding Space toggles once; holding an arrow repeats tick stepping. Other editing keys remain available. `node test_keyboard.cjs` verifies these cases using a read-only inspection client against8818, without changing desktop settings.

Snapshots preserve a numbered PNG, exact displayed pose, equipment transforms, parameters and camera. Refresh, snapshots and ordinary saved settings preserve your view. Settings can be exported/imported as JSON for later Unreal port work. The desktop client alone writes shared settings; plain browser visits are inspection views. Snapshot and state files live in this lab, independently of Attack Recovery Lab.

## Data and fidelity

`data/motions.json` contains the actual Unreal raw authored animation samples (30Hz):301 idle frames from `/Game/_mygame/M_Neutral_Stand_Idle_Loop` and121 forward-walk frames from the exported asset named in the file. `export_motion.py` regenerates through existing remote Python without saving or changing Unreal assets. Root travel is removed before the procedural pass so the upper-body walk can be inspected in place; the walk's pelvis height, sway, rotations and arm movement remain.

`data/unreal-setup.json` contains the current placed agent's holster transform relative to pelvis, the SwordRef seated local transform, grip transform, A_Sword component scale, blade-base marker and actual triangle geometry. The displayed sword uses the same Training mesh substituted by runtime Equip; length comes from the reference sword mesh. Scale is applied once. `export_setup.py` reads the editor scene without modifying it. Re-export intentionally changes the source fingerprint; old snapshots then require their original dataset.

`holster.js` retains progressive axial shrink around the grip, the2cm/5degree arrival gate,0↔100% slide, parenting and timed unshrink. Its lab arm path now uses the FK interpolation described below, with automatic guide-pose generation. It builds a deterministic60Hz trajectory; seeking and playback speed never alter the result. Drawing starts seated; sheathing starts held. Both actions now use the previous lab’s FK return framework from slide completion. Drawing unshrink runs alongside it with its own duration. The FK arm and additive body reach are lab experiments, not yet ported to Unreal.

**This is a pose/reach lab, not Jolt or a running NN.** It samples authored idle/walk and uses a pelvis rest attachment. It does not reproduce motor lag, physical hand/joint lag, collision impulses or recurrent NN changes. The original arm-only target setup was reach-limited by roughly4cm at35%, rather than the14cm measured in live Unreal. The corrected shrink-aware mouth target changes that historical comparison. The same arm solver, when fed the captured Unreal geometry, reproduces its14.143cm shortfall. With the new45° body reach, the tested35% idle/walk cases complete. Use the lab to develop the pose solution, then validate/port it in Unreal; passing this lab alone is not a physics-parity claim.

### Additive body reach

`bodyreach.js` fits spine_05 twist and clavicle_r swing to minimize shoulder distance to the **0% hand target** for both drawing and sheathing, accounting for the distributed spine's effect on positions. A bounded iterative three-variable search updates against each base-motion frame. Spine has one twist variable about the reference spine_05→neck_01 axis, expressed in its bone frame, and no added bend. Clavicle has two swing axes perpendicular to its reference clavicle_r→upperarm_r length axis: only axial clavicle roll is excluded, not world-Z turning. The shared angle limit bounds the absolute spine twist and total clavicle swing magnitude. Added turn advances at most speed/60 per tick; the original authored movement is not speed-clamped.

The accumulated spine_05 correction is applied as net component-space additions of20/40/60/80/100% to spine_01…05, preserving each frame's base orientation beneath it. These are total shares, not repeatedly stacked local offsets. Positions follow FK with original bone lengths; pelvis and legs are unchanged. Both arms inherit the body movement, with a further bounded swing on clavicle_r before right-arm FK interpolation. Head/neck authoring runs afterward, distributing the head’s correction through neck_01 and neck_02 while leaving spine_05 fixed; see Head look below.

Spine twist and clavicle swing both start at zero on the D/S start tick and are scheduled to finish on the FK hand-arrival tick, spreading the remaining rotation across the remaining reach time instead of always using maximum speed. Each angular-speed cap wins if the requested timing is too fast; the affected turn may then lag. The planner reconciles arm arrival with the scheduled torso pose. Both turns aim at the predicted arrival pose, avoiding last-tick catch-up as the gait moves. After arrival, drawing continues to follow the0% target. During sheathing, clavicle_r’s captured arrival correction instead fades linearly with insertion: full at0%, zero at100%, leaving the moving base clavicle pose underneath. The arm’s sliding guide poses are regenerated against this releasing shoulder. This release follows slide progress (and its timing curve), rather than the reach angular-speed limit; the spine retains its target turn until FK return starts. `test_spine_timing.cjs` verifies both spine and clavicle simultaneous arrival/no early finish in idle/walk S/D and the speed-limited exception. Drawing's grip/slide gate additionally waits until both applied turns are within0.25° of the fitted turn, even if the hand has already arrived. Sheathing keeps its original hand arrival gate. At slide completion, the FK return below takes the remaining upper-body correction back to the moving base pose.

`node test_bodyreach.cjs` checks limits, speed caps, spine twist without bend, clavicle swing without axial roll (including allowed world-Z turning), total spine shares, moving-base preservation, untouched pelvis/legs, bone lengths, shoulder-distance improvement, deterministic replay and a slow-turn/fast-hand drawing gate. `node test_bodyreach_ui.cjs` checks controls/state round-trip and captures draw/sheath stills through a read-only client. Evidence: `Saved/Diagnostics/SwordHolsterBodyReach/`. These checks do not certify motion quality; inspect playback in the lab.

### Head look

`headlook.js` authors the head toward the actual holster entrance: the seated reference blade-base point transformed by the moving holster. Look-in starts with D/S. It uses the rendered head’s local+Y facing axis and blends its target quaternion from original forward facing toward direct aim using **Look-at alpha**. It then advances under Max look-in angular velocity. At the selected action’s slide threshold, it starts returning to the current base animation’s forward-facing orientation under Max look-out velocity. Alpha controls only how strongly it aims inward; the forward return is complete. The superseded `headCorrectionAlpha` field is discarded on import.

For exponent greater than1, each phase captures its actual starting head orientation and uses the symmetric power sigmoid `u^p / (u^p + (1-u)^p)` toward its moving target. Duration is the initial angular distance divided by maximum speed, multiplied by the exponent (the sigmoid's peak slope). The per-tick angular cap additionally protects against target motion. Exponent1 keeps the original capped pursuit exactly. Look-out captures the current orientation even if look-in is unfinished. After the shaped transition, capped tracking follows the moving target. Both phases use independent exponents and ordinary playback time, unaffected by D/S curves.

The net correction relative to the spine-inherited pose is shared1/3 at neck_01,2/3 at neck_02, and fully at the head, preserving the underlying neck motion. These are total component-space shares, not stacked local amounts. Positions follow FK with unchanged bone lengths; spine_05, torso, arms and equipment are unaffected. The neck display now uses its own bone rotation rather than the head’s rotation. Aim is reevaluated from the shifted head position; the angular budget is applied once per authored60Hz tick. The head uses its own playback clock: reach/slide curve slopes do not multiply head angular speed. Its target follows the retimed holster, and look-out starts when actual slide progress crosses the threshold.

The head continues looking at the moving entrance until slide progress crosses its threshold. Its overlay stays independent while FK return changes the underlying body pose. If the arm never reaches the slide, look-out does not start. D/S completion now also waits for the head’s forward return, capped by the configured Timeline length; slow limits never cause an end snap. Existing draw unshrink and sword parenting remain intact. Seeking is deterministic because head poses are prepared with the rest of the recording.

`test_head_exponent.cjs` verifies sigmoid velocity in both directions, independent exponents, default linear motion, interrupted look-in, speed caps and completed return. `test_head_clock.cjs` covers both linear and shaped head motion under nonlinear D/S curves. `test_headlook.cjs` verifies0/.5/1 alpha, direct aim, both angular limits, independent/default/endpoint thresholds, weighted neck rotation, fixed spine anchor, preserved lengths, slow-look behavior and unchanged arm/equipment. FK, retiming and completion regressions pass. `test_retime_ui.cjs` also verifies all seven controls survive actual disk save, refresh, snapshot restore and JSON round-trip on an isolated test server. Still images: `Saved/Diagnostics/SwordHolsterRetime/head-look-in.png` and `head-look-out.png`. User motion inspection remains the final quality check.

### Independent reach and sliding retiming

The curves work like retiming separate sections of the existing recording. Each action owns a reach curve and a sliding curve; the UI reuses two contextual editors when the action changes. `retime.js` uses a monotone cubic through four editable points plus fixed endpoints. The reach curve remaps D/S start through hand arrival; the sliding curve remaps hand arrival through slide completion. Within each segment, the prepared body pose, moving base animation, spine/clavicle, FK arm, sword and shrink share source time, keeping alignment and coordinated arrival. Head/neck gaze is overlaid afterward on its independent playback clock. The base-motion ghost follows it too. Linear defaults preserve original sampling exactly.

Start, hand-arrival, slide-end and total duration stay fixed. Changing a reach curve cannot change sliding playback, and changing sliding cannot affect reach. Drawing’s unshrink/return phase keeps its existing timing. Edited points cannot reverse motion; horizontal sections may hold a pose. The existing velocity controls constrain the original prepared action, before intentional playback acceleration/deceleration. Unfinished phases use the available timeline endpoint; absent phases do not remap time. Diagnostics include playback and source time; captured model trajectories contain final displayed60Hz poses (including independent head and FK return); source body/arm frames are separately retained for curve edits.

The original `drawCurve` / `sheatheCurve` settings are retained as reach curves, preserving earlier edits; new `drawSlideCurve` / `sheatheSlideCurve` settings default linear. All are sanitized and copied independently. `test_retime.cjs` verifies phase/action independence, unchanged source body/arm poses, boundaries, shared body/equipment playback, forward head return and incomplete/unreachable cases. `test_retime_ui.cjs` uses its own temporary server/state directory to verify four distinct pointer-edited profiles, contextual display/action switching, numeric-setting retention, JSON round-trip, actual settings and snapshot disk writes, refresh and snapshot restore, independent reset and exclusive playback keys. Screenshot: `Saved/Diagnostics/SwordHolsterRetime/contextual-curves.png`. The user’s live lab state is untouched by testing.

### Shrink-aware holster mouth alignment

The seated hand target is derived from the **shortened sword**, keeping the authored blade-base marker at its original seated point. The old full-size hand target left the shortened base above the mouth; at35% shrink this produced a4.08cm axial tip gap at0% insertion despite the hand being on target. The correction first preserves the seated blade-base point, then inverts the scaled grip transform to obtain the hand target. The0% target moves outward by the shortened blade length, putting the tip at that same mouth plane. Axial-only shrink and grip pivot behavior remain intact; no asset or holster placement changes.

`test_mouth_alignment.cjs` covers five shrink values under two equipment orientations, and actual FK sheath/draw clear endpoints. Maximum axial error is0.000011cm (mesh/reference export precision); the authored small lateral placement offset is preserved. Read-only current-view comparison: `Saved/Diagnostics/SwordHolsterBodyReach/gap-live.json` and `gap-fixed.png`.

### FK arm interpolation and two-colour limbs

The user approved calculating destination poses automatically, then interpolating the bones as in Attack Recovery Lab. `armfk.js` reuses that lab's parent-local quaternion slerp, quintic easing, length-preserving offset interpolation and forward kinematics. The reach plan predicts the destination on the moving, turned body, solves that destination pose, and interpolates upperarm_r/lowerarm_r/hand_r local rotations from the captured starting pose. A few planning iterations reconcile destination time with the speed controls. The hand's orientation now interpolates with the arm instead of being assigned directly each tick.

Reach duration is bounded by the FK wrist arc and wrist/joint angular motion. **Max reach speed** and **Max reach rotation speed** limit the arm transition relative to its moving clavicle; inherited locomotion and body turning are additional movement. Reaching a close hand target does not allow a large elbow/wrist rotation to snap. Drawing still waits for the torso turn before gripping.

Sliding uses automatically prepared guide poses, spaced at most four ticks / about2cm along the sheath, then parent-local FK between them. Each guide reuses the previous arm orientation as its reference. The old analytic arm solver is used only to construct these guide/destination poses during preparation; sampling/playback never calls it. Tested35% idle/walk × draw/sheathe uses33–35 guide solves across full actions and stays within0.47cm of the intended grip while sliding. This is an approximation, not an exact hand constraint for every possible tuning. The former draw-only arm return tied to Unshrink Duration has been replaced by the common FK return below. Unshrink Duration now controls only sword size. Fractional playback samples also use FK, avoiding bone shortening from world-position interpolation.

The cyan half-capsules are reused from `ParryHarness/build_parry_harness.py` (`dhAddArmLongAxisHalf`), also used in Defense Harness. They follow each bone's own basis with the original quarter-turn / right-arm tint convention and0.8mm shell offset. Base tessellation matches the half-shell to avoid flicker. **View → Two-colour limbs** toggles them, persists with settings/snapshots and changes no solver data. Legs show the markers in full-body view.

Validation: `test_armfk.cjs` checks FK rotations, local-frame speed bounds, guide-only IK, fractional bone lengths, sheath tracking and continuous unshrink entry; `test_bicolor.cjs` checks bone-relative marker rotation and pose immutability. Body, original arm-only numerical fixtures, playback clamp, keyboard and bone-display regressions pass. Read-only UI checks cover marker toggle/state round-trip and screenshots. Evidence: `Saved/Diagnostics/SwordHolsterBodyReach/`. Playback quality still needs user inspection.

### FK return after drawing and sheathing

`fkreturn.js` adapts the unchanged `recovery.js` engine copied from Attack Recovery Lab. Both actions capture their actual slide endpoint; reaching/sliding guide calculations remain unchanged apart from the sheath clavicle release. Drawing returns the sword with the hand while unshrinking. Sheathing leaves the sword parented to the holster while the hand releases and the upper body returns. No slide guide or grip constraint is applied during the return.

The engine operates on the outgoing residual relative to the moving idle/walk base, in a fixed reference pose. Its parent-local FK interpolation, analytic angular momentum envelope, optional continuous spring, world/parent inertia modes, spine-angle duration adjustment and upperarm axial-inertia removal are reused directly. The result is transported back onto the current moving base pose, reaching it exactly at the return deadline. Root/pelvis/legs continue baseline motion. The World option refers to the recovery engine’s fixed reference before transport onto the moving base, not unconstrained world-space physics. Hands have no local inertia. Head/neck aiming is applied afterward and retains its independent timing/velocity limits.

Return elapsed time is ordinary playback time measured from slide completion, never remapped through reach/slide curves. Curves can affect the incoming velocity used to seed momentum; they do not alter return duration or its clock. Timeline completion waits for FK return, unshrink and head look-out, within the configured limit. Turning off return skips the recovery and retains the source action’s body pose. Profile edits preserve playing/paused state and reuse the planned body/arm trajectory. Drawing and Sheathing profile objects and bone weights are copied independently and saved in settings/snapshots/JSON; reopening the panel loads the active action’s profile.

`test_fkreturn.cjs` covers16 combinations of idle/walk, D/S, blend/spring and local/world inertia: exact entry, moving-base destination, lower-body preservation, attached drawing sword, unmodulated return duration, disable, independent profiles and sheath clavicle0→100% release. Updated FK/head/retiming/completion tests pass. `test_retime_ui.cjs` verifies right-side layout, contextual independent profiles, save/refresh/snapshot restoration and still captures on an isolated server. Evidence: `Saved/Diagnostics/SwordHolsterRetime/fk-return-panel.png`. Default sheath sliding hand error after clavicle release is0.019cm idle /0.183cm walk. User playback inspection remains necessary for motion quality and body/sword clearance; this is not a collision solver.

### Bone display basis correction

The reused renderer expects world XZY coordinates and a local X,-Y,Z bone basis. Converting the entire quaternion by the world Y/Z swap also swapped local bone axes, turning torso/head shapes sideways. `displayAxes` now converts each UE bone basis vector into the renderer convention directly, including reference ghosts and gizmos. Solver and equipment transforms remain in UE space unchanged. `node test_display.cjs` compares all26 frame-zero bones against the accepted recovery-lab idle axes (max4.75e-6 difference on toe bones from float32 source export). Idle/walk visual evidence is under `Saved/Diagnostics/SwordHolsterAxes20261010/`.

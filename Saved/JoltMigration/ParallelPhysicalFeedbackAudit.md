# Physical feedback batching: source-only audit

The current per-agent math has a viable joined parallel seam. Keep eligibility and all successful 25-transform samples on the game thread, then process distinct agent slices without moving any UObject access or current profiling accumulator onto workers. This has not been implemented or timed.

`StepSimulation` calls `ResamplePhysicalAgents` before `BuildInputBatch`, and includes both in NN BuildSeconds ([manager:2709](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:2709>)). Joining before that call preserves the 30 Hz recurrent input boundary. Agent eligibility at lines 2754-2768 reads live UObject flags, mode and physics state and must remain on GT. `SampleActualComponentPose` also stays on GT: the Jolt implementation explicitly checks GT, resolves weak components, updates its name cache and reads the current feedback-reference transform ([component:918](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyJoltCharacterComponent.cpp:918>)). The sampling path does not refresh animation or broadcast a delegate; the legacy path reads component/socket transforms ([Agent:3187](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyAgent.cpp:3187>)).

The worker seam starts after a successful sample at manager line 2791 and ends at 3013. Its current operations are raw lower/upper encoding, tolerance math, exact-equality branches, cleanup and recurrence copies. They use no UObject methods, NN inference, callbacks or container resizing. Shared reads are seed/root matrices, limb definitions, upper-arm definitions, bone/parent arrays and rest offsets. Agent reads are walk-policy selection, previous-sample state and that agent's tolerance map; the only FAgent mutation is `bHasPhysicalSample`. Fixed local `FSampledTrainingRotations` caches only the current sample ([manager:323](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:323>)).

Output ownership is disjoint: Physical/Prev/Cur/PreviousPhysical lower-state slices, four corresponding upper-state slices, UpperCurrentBase, previous/current pelvis-heading slices, and one agent flag. `StateSlice`, `UpperStateSlice`, `TransformStateSlice` and `TransformSlice` use agent-index strides ([manager:1039](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:1039>)); buffers are sized before use ([manager:2443](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:2443>)). Never resize the owning arrays while tasks run. The const `TMap::Find` tolerance reads are safe only while the maps are immutable; current setters mutate them on the public gameplay path at 4687/4707. Avoid per-worker implicit `FName(TEXT(...))` construction/global name-table work by preparing required tolerance values or known names on GT; no new tolerance semantics are needed.

The smallest change is to extract the existing post-sample math into one native helper shared by the serial and batch paths. In the batch path, collect only successful indices in ascending order, sample each into its existing fixed slice, then use one joined `ParallelFor` over those indices. Each task must receive only the native math inputs/output slices it needs. Count successful/failed physical samples on GT; workers must not increment the shared counters. Preserve failures by skipping all recurrence mutation when sampling fails. Preserve the existing synchronous `ResamplePhysicalAgentState` wrapper for `SetAgentSimulationMode` at line 4569, including its immediate pre-transition recurrence commit.

Keep the exact both-states-match branch at lines 2967-2975: it leaves the recurrent Prev/Cur pairs untouched. Preserve the first-sample versus subsequent-sample choice independently for lower and upper state, and set `bHasPhysicalSample` only at the same logical end. Moving all GT sampling before independent per-agent math has no cross-agent dependency in the inspected path.

UE 5.7's ordinary `ParallelFor` executes local items and then waits; it does not pump game-thread named tasks. Its optional pump branch is limited to the actual rendering thread ([ParallelFor.h:426](<C:/Program Files/Epic Games/UE_5.7/Engine/Source/Runtime/Core/Public/Async/ParallelFor.h:426>)). Therefore this synchronous region needs no new deferred owner framework. This is not permission to call manager gameplay APIs from workers or to let tasks outlive the join. Scheduler allocation and dispatch cost remain real.

Current `CharacterProfiling::FScope` and `RecordElapsed` assert GT and mutate shared frame counters ([profiling:245](<C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyJoltCharacterProfiling.cpp:245>)). The helper must contain none of those calls. Keep total ManagerPhysicalResample on GT; record a separate GT joined-math wall scope if attribution is needed. Retain serial raw-encoder timings only for the serial path, or explicitly distinguish any worker CPU sums from wall latency. Do not silently relabel worker time as the existing GT phase.

Required validation: compare the extracted serial and joined paths with identical native inputs, all lower/upper/heading output slices and sample flags, including walk/run, zero/partial/large tolerances, both-states-exactly-equal, one-state-equal, first/subsequent samples, failed/disabled/mixed agents and disjoint sentinels. Keep the raw encoder oracle `Prophecy.NN.PhysicalFeedback.RotationCacheRawEncoder`; it alone does not cover tolerance and recurrent-tail behavior. Then retain the full actual-NN100 moving/capsule/query/lifecycle gates and measure complete world time at unchanged cadence and model settings.

The retained normal/deferred pair measured roughly 0.542/0.544 ms physical resampling per world frame, of which approximately 0.109/0.111 ms is GT pose sampling and 0.080 ms is raw encoding. All post-sample math together has an upper serial-cost bound near 0.43 ms per world frame; GT preparation, dispatch, join, contention and bookkeeping reduce the attainable gain. A roughly 0.2-0.3 ms improvement is a hypothesis to test, not measured evidence or a solution to the remaining whole-pipeline gap.

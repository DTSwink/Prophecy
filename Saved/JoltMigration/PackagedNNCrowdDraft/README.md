# Current-source packaged NN crowd recipe

This directory contains the reviewed isolated recipe for **Development first, then Shipping**, using the current game module and actual lower/walk/upper CPU networks. R4 produced a complete Development 100-agent result (9.471366 ms mean; see `Docs/Jolt100AgentPerformance.md` for limits and subsequently identified correctness defects). The current manifest is `Saved/JoltMigration/NNCrowd-20260909-144331-647/snapshot-r5.json`, with six reviewed source corrections and the same 1,304 input set. R5 build/runtime validation is in progress; no Shipping runtime result exists.

The parent agent owns promotion and execution. The native-padding helper has been promoted; `NativePadding/Benchmark.merge.patch` is retained for provenance and must not be reapplied where those hooks exist. Endpoint caching was rejected and rolled back; Original feedback remains default. For the current project, use the revised R5 manifest directly with the Build/Run scripts. The initial snapshot creator below documents the original capture; its older eight-package closure requires the recorded R3 fresh dependency revision before cooking this project.

## Files and sequence

- `New-NNCrowdSnapshot.ps1` creates a new owned `Saved/JoltMigration/NNCrowd-<UTC-ms>/Project` copy. It never builds or launches UE.
- `Build-NNCrowdPackage.ps1` builds that snapshot's Editor, runs matching-source controlled query tests in Development, then uses official BuildCookRun to produce a new stage. Shipping requires a passing packaged Development runner result from the same snapshot. This script intentionally launches the bounded Editor automation/cook processes when the parent executes it.
- `Run-NNCrowdPackage.ps1` launches only the recorded direct staged Game executable, hidden at Normal priority, and validates fresh native JSON with `Validate-PackagedNNCrowd.py`. It does not build or cook. A timeout can terminate only the returned owned child process.
- `PackagedNN.Common.ps1` supplies copy/hash/path guards. Every report/directory is new; scripts never clean, delete or overwrite an earlier snapshot/stage/report.
- `NativePadding/` contains two new private game-module files and an isolated `Benchmark.merge.patch`. This is a dormant, explicit benchmark control, needed because default Shipping ignores the existing ExecCmds-based padding setter.

Reviewed command sequence, to be executed by the parent after the native seam and current source have been compiled:


Stop on any failed command and inspect its new report/log. These scripts do not invent a fallback package set, retry a failed cook, enable Shipping console/logging, replace the models, or lower validation coverage. The native P-class GT factor is explicit in every run above; omit it consistently for an unpinned comparison. Worker threads and process affinity remain governed by the existing controls. `-PauseChaos` is an optional separately labeled factor; the default sequence keeps ordinary Chaos maintenance. Do not run builds, other UE processes or agent tool activity during timed controls.

`Run-NNCrowdPackage.ps1` also accepts optional `-FeedbackMode Original|PreparedSerial|PreparedParallel`, defaulting to **Original**. It forwards the existing native `-PhysicsBenchFeedbackMode` selector and records the chosen mode in `runner.json`. Use the same explicit mode for Development and Shipping comparisons; changing it is a separately labeled factor, not an automatic packaging optimization. PreparedSerial and PreparedParallel use the existing captured GT inputs with serial/joined parallel math respectively. The runner changes no manager assets or original configuration.

The native padding seam captures one public `IConsoleVariable::FResolvedContext` before loading fixture meshes. Constructor defaults use explicit `ECVF_SetByConstructor`; non-default values resolve the highest current priority and tag once. It then uses the public string/context setter with nine significant digits, enough to round-trip the actual float CVar. It keeps the existing per-case/per-frame requested-padding checks and records original/applied/restored values and flags. Wrong methods, missing/read-only CVar, nonfinite inputs and wrong owner/world are refused. Effective value/flag changes from another setter cause explicit failure; owning `Finish`/`Deinitialize` restore the original flags and value using the captured context. Consequently `query_tree_settings_at_finish` can show the restored original value; the dedicated `native_query_padding_control` and existing measured-boundary rows prove the applied value. No production collision geometry/filter changes are made.

This is an isolated benchmark setting, not a general CVar-history transaction. Without unrelated tagged writes during ownership, replacing the current tagged row removes/re-adds the already-last row at that priority, preserving its tag and ordering; other existing rows remain untouched. A lazily allocated engine history object can remain after restoration. Same-value/same-priority external tag-only edits are not detected by the value/flags guard, and the helper does not claim to restore an arbitrary concurrently edited history snapshot. The default constructor case is the actual packaged recipe's expected admission; non-default tag behavior was source-reviewed, not independently runtime-tested here.

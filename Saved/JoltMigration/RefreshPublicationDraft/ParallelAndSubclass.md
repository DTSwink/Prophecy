# Parallel evaluation and direct-pose subclass audit

Source-only, 2026-09-09. No active edits, builds, asset changes or UE launches.

## Latest measurement changes the priority

Root reports the prepared composer plus legacy Chaos-finalizer ownership guard passed the same 100-agent case: 13.049 ms mean whole-world tick, 4.872 ms completed publication, 0.503 ms animation tick, 2.788 ms refresh including 1.390 ms query commit, 0.261 ms after-query finalization and 0.686 ms entire animation processing in engine CSV. Parallel evaluation can only move the last category off the game thread; it cannot eliminate game-thread query publication, animation tick or finalization. Its real benefit may be smaller than 0.686 ms after dispatch/completion overhead. No parallel implementation is recommended before larger costs are addressed.

## Supported parallel route, if measured later

UE `SkeletalMeshComponent.cpp:2714` dispatches parallel evaluation only when the real supplied `FActorComponentTickFunction` has a valid completion handle, threading is enabled, and the main/postprocess instances permit it. `RefreshBoneTransforms(nullptr)` deliberately takes the synchronous route. `DispatchParallelEvaluationTasks` at line 2855 swaps the component/context buffers, starts a weak-mesh worker task and a normal game-thread completion task, and attaches that completion to the supplied tick.

Our coordinator tick currently derives `FTickFunction`, not `FActorComponentTickFunction`. A real custom tick derived from the latter could override its execution/diagnostic methods and retain the coordinator's registered PrePhysics tick, using a separately named weak coordinator target. The base component target must be initialized and never used by our overrides. Passing a fabricated cast or borrowing an unrelated character tick is unnecessary and should not be done. `EngineBaseTypes.h:348` restricts completion-handle use to the current frame before the tick finishes.

There is no public getter for every mesh's private worker event. The minimal supported synchronous batch is therefore:

1. Create a coordinator-owned collection of immutable per-publication records, each with weak component/mesh/AnimInstance identities, exact native world/rig/registration/revision identities and owned completed-pose arrays.
2. For every surviving character, read/compose/publish its snapshot and call `RefreshBoneTransforms` with the executing coordinator's correctly typed tick. Handle both actual async dispatch and UE's valid synchronous fallback.
3. After dispatching all, drain each surviving mesh with public `HandleExistingParallelEvaluationTask(true, true)`. All workers were launched before these drains; completion may occur in any order while waiting. A single public `WaitAll` of mesh worker events is unavailable.
4. The normal native proxy post-evaluation hook commits that record's query pose before bone finalization. After a successful drain and exact identity checks, commit the character's completed revision. Keep the shared-step execution guard active until every queued publication is drained or safely discarded by mesh teardown.

`HandleExistingParallelEvaluationTask` waits then calls the normal completion path (`SkeletalMeshComponent.cpp:4737`). Already queued engine completion tasks check whether the mesh still has a pending worker reference before executing (`:415`), so they no-op after an explicit drain. Do not call `CompleteParallelAnimationEvaluation` blindly when there is no worker: it does not itself perform the same validity guard.

This requires real lifecycle work. Today's query delegate captures local variables by reference and is cleared immediately after synchronous Refresh returns; those captures cannot survive asynchronous return. Ordinary disable currently moves away State/destroys the rig before waiting for mesh tasks. In a parallel batch, ordinary disable must first complete an outstanding publication while its native ownership/query hook remains valid, then detach. Self-removal from its own finalization callback occurs after the worker reference was released and must not recursively drain the same publication. Unregister already waits with post-evaluation disabled in UE; removed/replaced identity records must not publish or fault remaining characters. Every failure path must drain already-dispatched work, and late admission remains deferred.

The newly added native proxy Evaluate profiling scope uses a game-thread-only accumulator. A parallel experiment must remove that unconditional worker access or use worker-local/atomic timing aggregated later on the game thread; reading the non-atomic enabled flag on workers is also inappropriate.

Tests would need mixed sync/parallel fallback, self-removal, removal of a different character whose worker is pending, immediate finalization ray checks, post-world ray checks, cancellation/unregister/world teardown, two worlds, and no leftover work before the next explicit step. Existing synchronous passing tests alone do not establish these async guarantees.

## Direct completed-pose subclass

A real `USkeletalMeshComponent` subclass is feasible; overriding its internal `EvaluateAnimation` is not: that method is private and nonvirtual (`SkeletalMeshComponent.h:2524`). `RefreshBoneTransforms` is virtual/public, and protected access lets a subclass correctly arm/flip component-space buffers. Epic's `UInsightsSkeletalMeshComponent::SetPoseFromProvider` demonstrates direct CS publication with protected flip bookkeeping, bounds invalidation and render dirtiness (`Plugins/Animation/GameplayInsights/Source/GameplayInsightsEditor/Private/InsightsSkeletalMeshComponent.cpp:9`). That editor playback implementation does not maintain ordinary local-pose data and callbacks and is not a gameplay replacement as written.

A production direct-pose class would need a dedicated completed-physics publication API. It can legally use public/protected transform/finalization operations, but:

* The only mutable full local-pose array remains the deprecated public `BoneSpaceTransforms` field; no nondeprecated mutable setter was found. Keeping local reads coherent would use that version-pinned field or require a new engine API. Component-space-only publication would silently leave local pose APIs stale.
* Full `FinalizeAnimationUpdate`, morph-target reset/override processing, stored evaluation context and custom attribute state are private. `PostAnimEvaluation` is public and runs the existing curve/callback/full finalizer path, but it expects those component buffers to have been prepared by evaluation. Its passed context does not install the context's transform arrays. Using it as an injection point would need a carefully bounded native-pose contract and tests for curves, hidden/LOD bones, root bounds offset and update-rate/cache flags; it is not a documented completed-pose setter.
* Reimplementing a subclass finalization tail can retain normal `FinalizeBoneTransform`, child transforms, overlaps, bounds, render and follower calls, but must explicitly preserve post-evaluation/notify/curve behavior. Skipping `TickAnimation` also skips its queued-event bookkeeping and update callbacks; the exact native class has no graph, but a generic subclass cannot assume that for arbitrary animation instances.
* The class must exist when `PhysicalMesh` is constructed. Its existing UObject cannot be changed into a derived C++ class in place. `NewObject<Derived>` in the transient benchmark demonstrates the implementation only; production's separate SCS-created PhysicalMesh needs deliberate Blueprint component/template migration before runtime. Retain the new production receiver identity throughout subsequent Jolt/Chaos switches, materials and stains.
* The stock editor `USubobjectDataSubsystem::ChangeSubobjectClass` is explicitly gated to native components (`SubobjectDataSubsystem.cpp:1506`) and its implementation replaces component instances. It does not establish safe in-place conversion of this SCS component. Native `SetDefaultSubobjectClass` likewise applies to native default-subobject creation, not this existing SCS mesh.

Epic's experimental UAF also has a friend extension that writes and flips an existing skinned component. Its header explicitly says these extensions are **not public API yet** (`Plugins/Experimental/UAF/UAF/Source/UAF/Internal/Component/SkinnedMeshComponentExtensions.h:14`). `CompleteAndDispatch` recomputes CS from its own LOD pose, omits skeletal local-pose/ordinary finalization callbacks and defers a custom GT tail. It is not a supported shortcut to copy or impersonate via the engine friend declaration.

Recommendation: do not adopt a new mesh class merely to pursue an unmeasured sub-millisecond-to-about-one-millisecond saving in the current 13 ms case. If a later benchmark justifies it, make component-class adoption and its version-pinned local-pose API explicit, validate visible rendering/blood/attachments/curves/previous buffers, and keep the current original-component path available until that production migration is proven. No runtime replacement of the live paint receiver is proposed.

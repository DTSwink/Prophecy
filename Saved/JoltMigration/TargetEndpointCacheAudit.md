# Reusing authored endpoints without reducing the 60 Hz target cadence

Source-only audit, September 9, 2026. No implementation, build, UE launch, settings change or performance claim.

**Recommendation:** cache only the immutable previous/future WORLD endpoints and the clean authored helper-local pose inside each live Jolt binding. Continue reading a valid current pose-store snapshot, recomputing interpolation alpha, applying the existing interpolation/rigid-forearm math, sampling controls, converting bone targets to body targets and publishing every 60 Hz frame. Treat this as a bounded candidate within the measured approximately 0.57 ms TargetRead and 0.17 ms HelperPose totals for 100 agents; it cannot explain or remove the remaining approximately 3 ms alone.

## Safe cache identity

A source revision is an efficient first rejection, but it is not a complete validity contract. Every public setter allocates a revision, including a local-only change or a carrier-only republish. The counter is global wrapping `uint32` (`ProphecyNNPoseTypes.cpp:12`); clear operations remove entries but do not reset the counter. Do not rely on ordering comparisons such as `NewRevision > CachedRevision`, or allow a cached pose to survive an unsuccessful source read.

For the first bounded implementation, keep unconditional current-snapshot retrieval and use the following hit contract. Equality is exact component equality, not tolerant `FTransform::Equals`, quaternion-sign equivalence or a hash-only comparison. Compare actual fields; do not compare padding bytes with `memcmp`.

| Dependency | Required treatment |
| --- | --- |
| Binding and source | Own cache in the character's opaque State; check current pose-source AgentId, manual data-source branch, weak mesh/component and skeletal/physics asset identities. Disable/rebind destroys the cache. Resolve source identity every call. |
| Snapshot revision and contents | Require matching nonzero revision, complete names/order and endpoint array sizes/values. Exact previous/current source arrays guard against revision wrap or a direct test caller changing values without updating its revision. A valid source read is required even on a hit. |
| Authored WORLD carriers | Match the two transforms stored **in the snapshot**, including translation, rotation and scale. The live physical mesh/world transform is not an input to this endpoint expansion and must not replace these authored carriers. |
| Reference and PHAT layout | Preserve current exact source-name, reference-name/parent and PHAT body-name/order checks. Asset pointer/count or BoneLayoutHash alone is insufficient. An index-layout rebuild invalidates endpoint data. |
| Reference-local values | Compare exact fallback reference transforms used by endpoint expansion. A simpler first implementation may compare the complete reference-local array once per call and share that result with helper validation. In-place ref-pose edits must invalidate even when index layout stays unchanged. |
| Helper-local source | Also compare `LocalTransforms` and full helper source names/order. Root/finger/helper-only changes can leave all body component-space endpoint arrays unchanged. Cache their clean local result separately. |
| Source time, interval and interpolation flag | Read fresh every call and recompute alpha. These need not invalidate immutable endpoint math, but they must never be cached as a completed target or suppress interpolation. |
| Live controls and offset conversion | Read strengths, enable/simulate controls, body offsets and current delta/substep denominator at their existing point on every publication. They are not properties of the endpoint cache. |

These exact checks avoid a pose-store API rewrite and retain the reader's current failure semantics. Their comparison/copy cost must be measured; the cache does not promise that all TargetRead time disappears. A later optimization could add an atomic Missing/Unchanged/Updated pose-store API with an explicit non-ambiguous publication/lifetime token. That is a separate change; the existing boolean IfNewer API is not sufficient.

## Why capsule correction and live callbacks still work

[Manager Tick](</C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:1742>) normally publishes after real 30 Hz inference steps, then calls `UpdateVisualRoots` every world frame. Free movement normally offers a reusable packet on intervening 60 Hz frames. The hit rate is not guaranteed to be 50 percent.

[Capsule correction](</C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyNNLocomotionManager.cpp:3896>) can rebase lower/upper recurrent and published states and call `PublishAgentPose` at line 3987 between NN steps. This setter creates a new revision, arrays and authored carriers; the next cache lookup must miss regardless of whether world engine frame or source time appears familiar. The manager's carrier construction at lines 3809-3849 includes capsule height and authored mesh-relative transform in the published snapshot. Nothing in the reader should implicitly rebase a cached endpoint using the latest physical presentation transform.

Each call still produces a fresh interpolated pose. In particular, alpha can advance with the same revision, interpolation can be disabled, frame delta can become greater than the pose interval, or a public interval/control can change. Existing world interpolation drops output scale to one and uses its custom rotation blend; preserve its exact math and order. Keep `ApplyRigidForearms` after interpolation every call: attack presentation is also tracked in a separate pose-store set and is not a snapshot field.

The existing callback regression changes only the later character's local root by 11 cm, republishes in the same frame, and verifies one serial fallback after the shared batch. That must remain a cache miss for helper data even if endpoint body arrays compare equal. **Do not skip successful `PublishRigVelocityTargets`, `AuthoredPublicationSerial++`, `LastPublicationFrame` or the fresh `BaseLocalPose` handoff on an endpoint-cache hit.** The completed-pose batch validates `AuthoredPublicationSerial` at [line666](</C:/Users/singerie/Documents/Unreal Projects/Prophecy/Source/GameAnimationSample3/Private/ProphecyJoltCharacterComponent.cpp:666>); keeping that independent serial protects same-frame callbacks even when a source packet's endpoint values happen to be identical.

## Minimal change shape

1. Add an optional **caller-owned** `FEndpointCache` in the existing private `ProphecyNNPhysicalTargetPose.h/.cpp`. Its cached outputs are target names, previous world endpoints and future world endpoints; current `FLayout::Evaluate` remains the miss-path implementation/oracle. No per-crowd global transform cache, retained UObjects or worker access is needed.
2. Add an optional cache pointer to the native `ReadNNFutureWorldPoseWithSnapshot` path (forward-declare its private namespace type in Agent.h). Existing Blueprint/public callers continue using no cache; only the live Jolt State passes its owned cache. This keeps the one existing reader's source resolution, alpha calculation, interpolation, rigid-forearm ordering and failure behavior authoritative. Alternatively use a second native overload with the same delegation if avoiding a default-argument signature change is preferable.
3. Cache a separate **clean, pre-fist** local array in character State, keyed by the valid snapshot's local data plus full reference-local/layout inputs. On each call copy that immutable array into `AuthoredLocalScratch`, then execute current fist preparation, guards, overlay and post-overlay validation. Never use `AuthoredLocalScratch` or `BaseLocalPose` itself as the clean cache: both participate in swaps and one may already contain a previous overlay.
4. Cache miss recomputes and validates the clean helper result. A hit can skip the redundant clean-result validation because the exact inputs and immutable cached result were already validated; retain the final post-overlay validation and all binding/callback guards. Commit cache validity only after successful computation.
5. Add opt-in benchmark counters for endpoint hits/misses, helper hits/misses and miss reasons (source revision, reference/layout, identity, failed source). Keep validation/counter serialization outside timing. No broad manager changes or source cadence edits.

Expected savings are modest: at ideal 50 percent reuse, 0.57 ms TargetRead yields a **0.285 ms absolute ceiling only if every part were skippable**, which it is not. Snapshot reading/copying, layout/identity comparisons, interpolation, rigid-forearm handling and output copies remain. The analogous HelperPose ceiling is 0.085 ms before retained copying/checks. The actual saving may be well below 0.2-0.3 ms, and capsule corrections lower the hit rate. Measure this candidate before depending on it for the full goal.

# Flattened servo publication: source proof only

2026-09-09. No implementation, build, or runtime test. Wait for the new `LastServoPrepareWall` timing before changing this path. Line numbers below refer to the active source around the idle-read promotion; function names are the stable anchors.

The world-level duplicate/finiteness validation is redundant for the current closed ownership route. A private accepted-packet commit seam can remove that repeated scan without relaxing validation at either existing publication boundary.

## Proof and preserved boundaries

1. `WorldSubsystem::PublishRigVelocityTargets` is the sole writer of a live rig's `Targets` values. It rejects non-GT/reentrant/faulted calls, resolves the rig's lifetime/generation, validates every target's current body handle and exact owner rig, rejects duplicate adapter slots, checks position/normalized rotation/nonnegative finite strengths, and rejects a nonpositive/nonfinite denominator. It clamps the accepted denominator once with the same `FMath::Max(h, UE_SMALL_NUMBER)` expression. Only after the entire stack-staged preflight succeeds does it replace the two accepted arrays. See `ProphecyJoltWorldSubsystem.cpp`, `PublishRigVelocityTargets` (formerly 1153–1202).
2. `AddNative` creates a fresh native Jolt body, assigns it to an unused adapter slot, and assigns exactly one `OwnerRig`. Two committed rigs cannot share a body. `CreateRig` publishes `bCommitted` only after its bodies and constraints are complete. `FindRig` requires that bit. See `AddNative` (667–701 after promotion), `CreateRig` (1107–1143).
3. Per-rig duplicate adapter-slot rejection plus disjoint rig ownership implies globally distinct native BodyIDs when accepted arrays are concatenated. Slot/native identity cannot change underneath a stored target: public `DestroyBody` rejects any rig-owned body; whole-rig destruction clears the flattened listener packet and deletes that rig's accepted packet before deleting its bodies. A replacement rig receives a new generation and initially has no targets. No API transfers a live body between rigs. See `DestroyRigSlot`, `DestroyBody`, and `AllocateRigSlot`.
4. `PrepareServoPacket` appends only committed, nonempty accepted arrays, preserving rig traversal and per-rig target order. It does not modify any copied field. Step holds its synchronous owner guard through preparation, activation, Update, and sample capture. There is no user callback between flattening and publication.
5. Nevertheless, `FVelocityServo::PublishPerTarget` currently builds a fresh `TSet<uint32>` and repeats body-sentinel/duplicate/position/quaternion/strength/denominator checks over that already accepted flat array. For 100 fully targeted 22-body rigs, this is 2,200 entries each Step. This is an operation count from code, not a measured timing or allocation count.

The repeated packet validation does **not** replace the native body checks in `PrepareActivation` and `OnStep`, nor the arithmetic overflow checks in `CalculateRewrite`; keep those live checks unchanged.

## Smallest candidate if the timing justifies it

Extract only the existing accepted-array commit tail of `PublishPerTarget` into a private method, for example `CommitValidatedTargets(TConstArrayView<FTarget>)`. Keep the public/native `PublishPerTarget` complete validation exactly intact, then call that private tail. Give only the global native owner `FProphecyJoltWorldState` friendship and call the private tail from its `PrepareServoPacket`, whose inputs satisfy the proof above. Do not expose a public `bTrustInput` flag or an externally callable unchecked publication API.

Retain the existing tail verbatim: copy targets with capacity reuse; denominator `Max` normalization; sample sizing/reset; mixed-versus-uniform denominator diagnostic; empty-packet behavior. Retain GT assertion/owner contract at the private seam. The world wrapper can reset its `Error` and return success after the accepted commit; activation remains separately fallible. Do not combine this with reference-lifetime changes, removing the flat copy, sample reset changes, or caching body state.

Tests already exercising the world route are `Prophecy.Jolt.MultiRig.IndependentPacketsOneWorldStep` (foreign-rig and duplicate publication rejected atomically, distinct per-rig denominators and outputs), `RemovalGenerationAndWorldLifetime` (remove/recreate while retaining another rig), and `RigWorld.ServoHandlesAndWholeRigRemoval`. Existing standalone servo tests retain the validated entry point. If implementing, add bounded direct rejection checks for invalid/nonfinite public inputs preserving the previous accepted packet, plus an empty-per-rig publication clearing only its own output. Do not test only that a new bypass flag is set; compare actual velocity/sample results and survivor identities.

The new preparation timer includes flattening, copies, sample reset and denominator aggregation as well as validation. Its full value is an upper bound for removing the duplicated `TSet`/predicate pass.
